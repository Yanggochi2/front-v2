# Router (초안)

> Figma 화면 이름 기준으로 새로 정한 경로다. 경로 이름은 추측이며 팀 확정 시 수정한다.

## 사이드바 있음 — `src/app/(app)/`
| 경로 | 화면 | Figma 프레임 |
|---|---|---|
| `/schedule` | 근무표 시트 | v3.1-A, 근무표 시트 · 빈 표, 빈 상태 · 근무표 |
| `/schedule/generate` | 자동 생성 시작(`?ym=`) · 진행(`?jobId=`) | 자동 생성 진행 (시작 화면은 시안 없음) |
| `/schedule/generate/failed` | 생성 실패 · 해 없음 | 생성 실패 · 해 없음 |
| `/nurses` | 간호사 명단 | 간호사 명단, 빈 상태 · 간호사 명단 |
| `/nurses/new` | 간호사 등록 | 간호사 등록 |
| `/nurses/[nurseId]/edit` | 간호사 정보 수정 | 간호사 등록 화면 확장 |
| `/rules` | 규칙 설정 | 규칙 설정 |
| `/stats` | 통계·공정성 | 통계·공정성, 빈 상태 · 통계·공정성 |
| `/audit-log` | 감사 로그 | 감사 로그, 빈 상태 · 감사 로그 |
| `/ward-settings` | 병동 설정 | 병동 설정 |

월별 보기(`월별 보기 · 사이드바 열림`)는 별도 경로 없이 `/schedule?view=month`(주간/월간 보기 전환)로 둔다.
`/schedule`을 보기·기간 없이 처음 열면 월간으로 열린다. 주간 보기와 주 선택 링크는 `ym`·`week`를 달고 있어 그대로 주간이다.
그 달 근무표가 없으면(404) 자동 생성으로 보내는 안내를 보여 준다.
사이드바 화면은 모두 관리 링크로 들어온 수간호사 화면이다 (10/26 계약, 로그인·역할 구분 없음). 관리 토큰이 없거나 바뀌면(401) `/manage`로 보낸다.

## 사이드바 없음 — `src/app/(onboarding)/`
| 경로 | 화면 |
|---|---|
| `/manage` | 관리 링크 진입. `#token=`을 저장하고 주소창에서 지운 뒤 `/schedule`로 보낸다. 토큰이 없거나 바뀌었으면 안내(새 병동 만들기) |
| `/onboarding/create-ward` | 병동 만들기 (`POST /workspaces`). 만든 뒤 관리 링크를 보여 주고 저장하게 한다 |

- 로그인·회원가입·소속 선택·승인 대기·신청·가입 승인·마이페이지(`/login`, `/signup`, `/onboarding/select-ward`, `/onboarding/pending`, `/requests`, `/approvals`, `/me`)는 10/26 범위 변경으로 없앴다.

## 공유 링크 — `src/app/(shared)/`
| 경로 | 화면 |
|---|---|
| `/shared/[token]` | 로그인 없이 보는 확정 근무표 (`GET /shared/schedules/{token}`). 월간, 정렬 `?sort=name`(없으면 숙련도순), 인쇄·PDF만. 링크가 바뀌었거나 꺼졌으면(404) 안내. 검색 제외·Referer 안 보냄 |

- 수간호사는 확정·지난 근무표의 머리에 있는 "공유 링크"에서 링크를 만들고·복사하고·다시 만들고·끈다. 확정을 취소하면 링크는 백엔드가 지운다.

## 랜딩 — `src/app/(marketing)/`
| 경로 | 화면 |
|---|---|
| `/` | 서비스 소개 랜딩 (3D 배경, 섹션 앵커 #hero ~ #cta) |

## 진입
- 앱의 시작 화면은 `/schedule`이다. 사이드바를 닫았을 때의 로고도 `/schedule`로 간다.
- 랜딩의 "시작하기"는 `/onboarding/create-ward`, "관리 화면"은 `/manage`로 간다.
